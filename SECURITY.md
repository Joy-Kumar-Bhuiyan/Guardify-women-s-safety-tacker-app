# Security policy

Only the latest deployed release from `production-ready` is supported during pre-launch.

Do not open a public issue for vulnerabilities involving authentication, location, contact details, share links, provider credentials, or abuse/stalking scenarios. Use GitHub private vulnerability reporting. If unavailable, contact the repository owner through a private verified channel and request an encrypted route.

Include reproduction steps, affected commit, impact, and safe evidence. Do not access another person's data, trigger real notifications, or test production accounts without written authorization.

Maintainers should acknowledge within 3 business days, provide triage within 7 business days, coordinate remediation, rotate exposed credentials immediately, and credit reporters unless anonymity is requested.
