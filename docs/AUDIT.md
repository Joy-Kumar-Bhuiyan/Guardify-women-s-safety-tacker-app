## Injection review

No SQL or command execution exists in the baseline. Firebase path concatenation and unvalidated objects remain injection-like trust-boundary problems. The target design uses explicit schemas, rejects keys such as `__proto__`, does not accept arbitrary Firestore paths/operators, and never passes user data to a shell.

## WebSocket review

No WebSocket implementation exists. The baseline's real-time Firestore listeners are browser-to-database and do not provide an application authorization layer. The target begins with rate-limited HTTPS polling for share links; authenticated SSE may be added only with room-level authorization, heartbeat, and backpressure tests.

## History caveat

Working-tree cleanup cannot revoke or erase secrets from Git history. All pre-audit credentials are considered compromised until the owner completes `SECRETS_ROTATION.md`; a coordinated history rewrite is a separate manual action.

## Final re-audit (production-ready branch)

All Critical and High inherited findings above are resolved in the current tree: browser database access was removed and denied by rules; server-derived authorization and strict validation protect resources; sensitive fields and outbox destinations are encrypted; application sessions use rotating hashed refresh credentials in HttpOnly cookies; exact-origin, security-header, request-limit, redaction, idempotency, consent, expiry, revocation, retention, audit, CI, and tested negative-access controls are present. Production dependency audits report zero vulnerabilities.
